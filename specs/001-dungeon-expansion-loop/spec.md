# Feature Specification: ダンジョン領域拡張ループ

**Feature Branch**: `main`

**Created**: 2026-07-25

**Status**: Draft

**Input**: User description: "マインスイーパーの推理とダンジョン探索を組み合わせ、危険物処理、領域拡張、難易度選択、死亡地点からの回収、再開可能な探索を提供する"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 推理しながら探索範囲を広げる (Priority: P1)

プレイヤーは入口付近の安全地帯から探索を始め、開放済みマスの数字を読み、
隣接する安全な壁を壊して移動可能な範囲を広げる。上下左右と斜めの8方向へ
移動できるが、壁、未探索マス、斜め方向の塞がれた角を通り抜けることはできない。

**Why this priority**: 推理、移動、壁破壊、領域拡張を一体化した本作の中核体験だからである。

**Independent Test**: 固定された小規模ダンジョンで、入口から数字を読み、安全な壁だけを
壊し、未探索領域を直接通過せずに新しい部屋まで到達できることで検証できる。

**Acceptance Scenarios**:

1. **Given** 入口周辺だけが開放されたダンジョン、**When** プレイヤーが開放済みの
   隣接マスへ8方向入力を行う、**Then** 壁と塞がれた斜め角を通過せず移動できる。
2. **Given** プレイヤーに隣接する危険物のない壁、**When** 必要なスタミナを使って
   壁を壊す、**Then** 壁の先が開放され、通路、部屋、素材、宝箱のいずれかを確認できる。
3. **Given** 周囲8マスに危険物が3個ある安全マス、**When** そのマスを開放する、
   **Then** マス中央に「3」が表示され、実際の危険物数と一致する。
4. **Given** 壁または未探索マスが移動先にある、**When** プレイヤーがその方向へ
   移動する、**Then** プレイヤーは現在の開放済みマスから出ない。

---

### User Story 2 - 危険箇所を印付けして安全に処理する (Priority: P1)

プレイヤーは数字から危険物の位置を推測し、疑わしい壁へ危険マークを付けて
誤破壊を防ぐ。危険マークの付いた壁に道具を使って危険物処理を行い、正解なら
通常より価値の高い報酬を得る。

**Why this priority**: 推理を明示的な判断と報酬へ変える主要アクションだからである。

**Independent Test**: 危険物が既知の盤面で、マークの切り替え、通常破壊の防止、
正解処理の報酬、誤処理の消費を個別に確認できる。

**Acceptance Scenarios**:

1. **Given** 未開放の壁、**When** プレイヤーが危険マークを付ける、**Then** その壁は
   通常の壁破壊対象から保護され、再度同じ操作を行うとマークが外れる。
2. **Given** 危険物があるマーク済み壁と使用可能な処理道具、**When** 危険物処理を行う、
   **Then** 危険物が安全に除去され、スタミナと道具耐久値が減り、高価値報酬が抽選される。
3. **Given** 危険物がないマーク済み壁、**When** 危険物処理を行う、**Then** スタミナだけが
   消費され、道具耐久値は減らず、報酬も出現しない。
4. **Given** 危険マークのない壁、**When** 危険物処理を選ぶ、**Then** 処理は開始されず、
   マークが必要であることが表示される。

---

### User Story 3 - 資源を管理して探索を継続する (Priority: P2)

プレイヤーは壁破壊、危険物処理、攻撃にスタミナを使い、歩行と走行を使い分ける。
危険物処理道具の耐久値、所持素材、HPを確認しながら、素材、宝箱、モンスターの
報酬を回収して探索を続ける。

**Why this priority**: 推理だけでなく探索継続の判断と拠点成長につながる資源循環を作るためである。

**Independent Test**: 同じ探索区画で各行動前後のHP、スタミナ、道具耐久値、所持素材数を
比較し、回復、枯渇、報酬取得を確認できる。

**Acceptance Scenarios**:

1. **Given** 十分なスタミナ、**When** 壁破壊、正しい危険物処理、攻撃を行う、
   **Then** 行動ごとに定められたスタミナが減る。
2. **Given** 通常歩行中、**When** 8方向へ移動する、**Then** スタミナを消費しない。
3. **Given** 走行中、**When** 移動を継続する、**Then** 通常歩行より速く移動し、
   移動時間に応じてスタミナが減る。
4. **Given** 道具耐久値が0、**When** 危険物処理を試みる、**Then** 処理できず、
   拠点での修理が必要であることが表示される。
5. **Given** 素材、宝箱、倒したモンスターの報酬がある、**When** プレイヤーが回収する、
   **Then** 所持数へ反映され、画面上の表示も同じ値へ更新される。

---

### User Story 4 - チェックポイントを確保して陣地を拡張する (Priority: P2)

プレイヤーは開始前に提示されたクリア条件を満たし、入口または既存陣地から安全な道筋が
つながったチェックポイントへ到達する。確保に成功すると、その道筋と開放済み範囲が
永続的な自陣として拡張され、次の探索や最奥地への進行に利用できる。

**Why this priority**: 一回の探索成果を長期的な領域拡張へ変える進行目標だからである。

**Independent Test**: チェックポイント到達だけの条件と、危険物除去数、素材回収数、
ボス撃破を伴う条件をそれぞれ満たした場合と満たさない場合で確保結果を比較できる。

**Acceptance Scenarios**:

1. **Given** 到達のみが条件のチェックポイントと安全な連続経路、**When** プレイヤーが
   到達する、**Then** チェックポイントと到達までの開放済み範囲が自陣になる。
2. **Given** 危険物除去数または素材回収数が条件、**When** 未達の状態で到達する、
   **Then** 未達項目が表示され、達成後に確保できる。
3. **Given** ボス撃破が条件のチェックポイント、**When** ボスを倒して到達する、
   **Then** チェックポイントを確保できる。
4. **Given** チェックポイントを確保済み、**When** ゲームを終了して再開する、
   **Then** 拡張された自陣と進行状況が保持される。

---

### User Story 5 - 探索失敗後に落とし物を回収する (Priority: P2)

プレイヤーは危険物やモンスターでHPが0になると自陣へ戻される。装備していた道具、
武器、防具と探索中に得た素材の一部は死亡地点に残り、次の探索で回収できる。

**Why this priority**: 失敗へ緊張感を与えながら、取り戻すための次の探索目標を生むためである。

**Independent Test**: アイテムを持った状態で探索に失敗し、自陣復帰、死亡地点表示、
次回探索での回収、再読み込み後の保持を一連で確認できる。

**Acceptance Scenarios**:

1. **Given** 探索中のプレイヤーのHPが0になる、**When** 失敗処理が完了する、
   **Then** プレイヤーは自陣へ復帰し、死亡地点と落とした内容を確認できる。
2. **Given** 死亡地点に落とし物がある、**When** 次の探索でその地点へ到達する、
   **Then** 落とした装備と素材を回収できる。
3. **Given** 未回収の落とし物、**When** ゲームを終了して再開する、**Then** 死亡地点と
   内容が保持される。
4. **Given** 未回収の落とし物がある、**When** プレイヤーが「はじめから」を確定する、
   **Then** 消失する対象が事前表示された後、落とし物を含む探索進行が初期化される。

---

### User Story 6 - 難易度を選んで自動生成ダンジョンへ挑む (Priority: P3)

プレイヤーは探索開始前に「優しい」「普通」「難しい」から難易度を選ぶ。難易度に応じて
マップ規模、危険物、部屋、モンスター、壁、宝箱の構成が変わるが、開始地点の安全性と
数字の正確性は常に維持される。

**Why this priority**: 同じ中核ルールを異なる緊張度と報酬期待で繰り返し遊べるようにするためである。

**Independent Test**: 同じ生成条件で3難易度の概要と生成結果を比較し、各難易度の傾向、
開始地点の安全性、数字と危険物の一致、到達可能なチェックポイントを確認できる。

**Acceptance Scenarios**:

1. **Given** 探索開始前、**When** 難易度を選ぶ、**Then** 変化する主要項目と
   想定報酬が開始前に表示される。
2. **Given** 任意の難易度、**When** ダンジョンを生成する、**Then** 初期位置周辺に
   危険物がなく、入口から少なくとも1つのチェックポイントへ到達可能である。
3. **Given** 生成済みダンジョン、**When** 全ての開放済み数字を検査する、**Then**
   各数字が現在有効な周囲8マスの危険物数と一致する。

---

### User Story 7 - 新規開始、再開、設定変更を選ぶ (Priority: P3)

プレイヤーはタイトル画面からゲーム開始または設定を選ぶ。ゲーム開始では保存状態に応じて
前回終了直前から再開するか、新しく始めるかを選択できる。

**Why this priority**: 長期進行を安全に再開し、端末や好みに合わせて操作できる入口だからである。

**Independent Test**: 保存データがある場合とない場合でタイトル遷移を比較し、再開位置、
新規開始の確認、音量と操作方法の保持を確認できる。

**Acceptance Scenarios**:

1. **Given** タイトル画面、**When** 「ゲーム開始」を選ぶ、**Then** 「つづきから」と
   「はじめから」が表示される。
2. **Given** 有効な探索中断データ、**When** 「つづきから」を選ぶ、**Then** 前回終了直前の
   ダンジョン、位置、状態から再開する。
3. **Given** 保存データがない、**When** 「つづきから」を確認する、**Then** 選択不能で
   理由が表示される。
4. **Given** 既存進行がある、**When** 「はじめから」を選ぶ、**Then** 消去対象の確認を
   経なければ初期化されない。
5. **Given** 設定画面、**When** 音量または操作方法を変更する、**Then** 即時反映され、
   次回起動後も保持される。

### Edge Cases

- 生成条件を満たす配置候補が不足する場合は、危険物数などを安全側へ減らし、
  生成不能の盤面を開始しない。
- 斜め移動時に横または縦のどちらかが壁なら、角抜けを許可しない。
- 危険マーク中の壁へ通常破壊を入力しても、マークを解除するまで破壊しない。
- スタミナ不足、道具耐久値0、所持上限到達時は、資源を負数にせず行動理由を表示する。
- 危険物除去後は、影響範囲の数字を現在有効な危険物数へ更新する。
- 複数の危険物効果が同時発生しても、HP、状態異常、モンスター出現を重複適用せず
  一度の作動として解決する。
- チェックポイントへ到達しても、安全な連続経路または提示済み条件が不足していれば
  陣地化しない。
- 中断データが破損している場合はバックアップを試し、復元不能なら新規開始を案内する。
- ゲームが非アクティブな時間を利用して、走行コストや危険効果を進行させない。
- 未回収の死亡地点が複数ある場合は全て保持し、地図上で区別できる。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: ゲームはマス目状の見下ろし型ダンジョンを提供しなければならない。
- **FR-002**: プレイヤーは開放済みで歩行可能なマスへ8方向に移動できなければならない。
- **FR-003**: ゲームは壁、未探索マス、塞がれた斜め角、他の通行不能物を通過させてはならない。
- **FR-004**: ゲーム開始時は入口付近だけを開放し、その周辺を危険物のない安全地帯に
  しなければならない。
- **FR-005**: プレイヤーは隣接する未開放の壁だけを破壊できなければならない。
- **FR-006**: 安全なマスは、現在有効な周囲8マスの危険物数を正確に表示しなければならない。
- **FR-007**: 数字0は省略でき、1は青、2は緑、3は赤、4は紫で区別しなければならない。
- **FR-008**: 壁の先には通路、部屋、素材、宝箱、危険物、モンスターを配置できなければならない。
- **FR-009**: 未処理の危険物がある壁を壊した場合、対応する危険効果を一度だけ作動させなければならない。
- **FR-010**: 危険物は少なくとも爆発、毒、ガス、落石を区別し、作動時に種類と結果を
  プレイヤーへ示さなければならない。
- **FR-011**: 危険物の作動はHP減少、状態異常、障害物発生、モンスター出現のうち
  種類に応じた結果を発生できなければならない。
- **FR-012**: プレイヤーは未開放の壁へ危険マークを付け、同じ操作で外せなければならない。
- **FR-013**: 危険マーク中の壁は通常の壁破壊から保護されなければならない。
- **FR-014**: 危険物処理は危険マークの付いた隣接壁だけを対象にしなければならない。
- **FR-015**: 正しい危険物処理は危険物を安全に除去し、通常採取より高価値の報酬機会を
  提供しなければならない。
- **FR-016**: 誤った危険物処理はスタミナだけを消費し、道具耐久値を減らさず、
  報酬を発生させてはならない。
- **FR-017**: 危険物が除去された場合、影響を受ける数字は現在の危険物数へ更新されなければならない。
- **FR-018**: 壁破壊、正しい危険物処理、攻撃はそれぞれ所定のスタミナを消費しなければならない。
- **FR-019**: 通常歩行はスタミナを消費せず、走行は移動時間に応じてスタミナを
  消費しなければならない。
- **FR-020**: スタミナはアクティブな探索中の時間経過と回復アイテムで回復できなければならない。
- **FR-021**: スタミナ不足時は対象行動を開始せず、不足理由を表示しなければならない。
- **FR-022**: 危険物処理道具は耐久値を持ち、正しい処理に使うたびに減少しなければならない。
- **FR-023**: 耐久値0の道具は使用不能となり、拠点で修理または強化できなければならない。
- **FR-024**: 素材とアイテムは壁破壊、危険物処理、宝箱、モンスター撃破から
  入手できなければならない。
- **FR-025**: 帰還した素材は拠点で道具作成、修理、強化、売却に利用できなければならない。
- **FR-026**: ダンジョンはチェックポイントと、その探索前に確認できるクリア条件を
  持たなければならない。
- **FR-027**: クリア条件は到達、危険物除去数、素材回収数、ボス撃破を単独または
  組み合わせて表現できなければならない。
- **FR-028**: 条件達成と、入口または既存陣地からの安全な連続経路の両方を満たした場合だけ、
  チェックポイントを確保できなければならない。
- **FR-029**: 確保時はチェックポイントまでの開放済み連続範囲を自陣として永続化しなければならない。
- **FR-030**: 最奥地のチェックポイントまたは最終ボスの達成を、そのダンジョンの
  最終目標として提示しなければならない。
- **FR-031**: HPが0になった場合、探索を失敗として終了し、プレイヤーを既存の自陣へ
  復帰させなければならない。
- **FR-032**: 探索失敗時は装備中の道具、武器、防具と、その探索で得た回収前素材の50%を
  端数切り上げで死亡地点へ落とさなければならない。
- **FR-033**: 死亡地点の落とし物は回収または新規ゲーム確定まで保持し、複数地点を
  個別に保存・表示しなければならない。
- **FR-034**: プレイヤーは死亡地点へ再到達することで落とし物を全て回収できなければならない。
- **FR-035**: ダンジョンは探索開始時に自動生成されなければならない。
- **FR-036**: プレイヤーは「優しい」「普通」「難しい」の3難易度から選択できなければならない。
- **FR-037**: 難易度はマップ規模、危険物数、部屋数、モンスター数と強さ、壁量、
  宝箱数、報酬傾向へ反映されなければならない。
- **FR-038**: どの難易度でも開始地点の安全性、数字の正確性、チェックポイントまでの
  到達可能性を保証しなければならない。
- **FR-039**: 画面はHP、スタミナ、装備中道具、道具耐久値、所持素材数、現在の
  クリア条件を探索中に確認できる形で表示しなければならない。
- **FR-040**: タイトル画面は「ゲーム開始」と「設定」を表示しなければならない。
- **FR-041**: 「ゲーム開始」は「つづきから」と「はじめから」を表示しなければならない。
- **FR-042**: 有効な中断データがある場合、「つづきから」は終了直前のダンジョン、位置、
  プレイヤー状態、盤面、敵、落とし物、進行条件を復元しなければならない。
- **FR-043**: 「はじめから」は消去対象を示す確認を経た後だけ、探索進行と未回収の
  落とし物を初期化しなければならない。
- **FR-044**: 設定では音量と操作方法を変更でき、変更を次回起動後も保持しなければならない。
- **FR-045**: UIはスマートフォン縦画面を基準に、画面寸法、safe-area、入力方式へ
  適応し、主要操作に44px以上の操作領域を確保しなければならない。
- **FR-046**: ゲームは初回利用後、通信できない状態でも保存済み探索を開始または
  再開できなければならない。
- **FR-047**: 永続進行、探索中断、死亡地点のデータは版番号を持ち、破損時に
  バックアップからの復元を試みなければならない。

### Constitution Requirements _(mandatory)_

- **CR-001 — Core loop**: 推理、8方向移動、壁破壊、危険物処理、戦闘、回収、
  チェックポイント確保、領域拡張、最奥地への進行を一つの反復可能な探索として扱う。
- **CR-002 — Danger and recovery**: 開始地点の安全性と周囲8マスの数字一致を常に保証する。
  死亡時の装備と素材損失、死亡地点、回収方法、唯一の消失条件である新規ゲーム確定を
  事前に表示する。
- **CR-003 — Adaptive UI/PWA**: スマートフォン縦画面を基準に、タッチ、ポインター、
  キーボード入力とsafe-areaへ適応する。初回利用後のオフライン起動と再開を対象に含める。
- **CR-004 — Save compatibility**: 既存の永続セーブと探索中断セーブを維持しつつ、
  難易度、危険物種別、道具耐久、チェックポイント、自陣、死亡地点を版管理された
  データとして追加する。既存データは進行を失わず移行できなければならない。
- **CR-005 — Verification**: 盤面生成、数字計算、移動衝突、マーク、危険物処理、
  スタミナ、耐久、死亡ドロップ、チェックポイント、難易度、セーブ移行を個別検証し、
  タイトルから再開、探索、死亡回収、確保、拠点帰還までの利用者経路も検証する。

### Key Entities _(include if feature involves data)_

- **プレイヤー**: 現在位置、HP、スタミナ、行動状態、装備、所持品、自陣との関係を持つ探索者。
- **ダンジョン**: 生成条件、難易度、マス、部屋、入口、チェックポイント、最奥地を含む探索空間。
- **マス**: 座標、開放状態、壁、歩行可否、周囲危険物数、内容物を表す最小単位。
- **危険物**: 種類、作動状態、処理状態、効果、報酬、危険マークとの関係を持つ隠された脅威。
- **危険マーク**: プレイヤーが未開放マスへ付ける推測状態で、通常破壊を保護する。
- **処理道具**: 種類、現在耐久値、最大耐久値、強化段階、修理状態を持つ装備。
- **チェックポイント**: 位置、達成条件、安全経路、確保状態、拡張対象範囲を持つ進行地点。
- **自陣**: 確保済みチェックポイントと連結した永続的な安全・開放範囲。
- **死亡地点**: 座標、落とした装備と素材、回収状態、関連するダンジョンを持つ回収対象。
- **探索状態**: ダンジョン、プレイヤー、敵、取得物、条件進捗、死亡地点を再開可能にまとめた状態。
- **難易度**: 生成規模、配置密度、敵強度、報酬傾向を決める「優しい」「普通」「難しい」の選択。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 初回プレイヤーの90%以上が、説明を見ながら10分以内に数字を使って
  危険箇所を1つ正しくマークし、安全処理できる。
- **SC-002**: 生成された10,000件のダンジョン全てで、開始地点周辺に危険物がなく、
  全数字が周囲8マスの有効危険物数と一致する。
- **SC-003**: 生成された全ダンジョンで、入口から少なくとも1つのチェックポイントまで
  ルール上到達可能な経路が存在する。
- **SC-004**: プレイヤー入力後100ミリ秒以内に移動、マーク、壁破壊開始の視覚反応が現れる。
- **SC-005**: 対象となる320pxから430px幅の縦画面全てで、主要HUDと操作が
  画面外へ欠けず、44px以上の操作領域を維持する。
- **SC-006**: 有効な中断データを使った再開試験の100%で、位置、盤面、HP、スタミナ、
  道具耐久、敵、条件進捗、死亡地点が終了直前と一致する。
- **SC-007**: 死亡回収試験の100%で、規定量の装備と素材が死亡地点へ移動し、
  再到達後に重複や欠損なく回収される。
- **SC-008**: チェックポイント確保試験の100%で、条件未達時は確保されず、
  条件達成時だけ連続した開放範囲が自陣として保存される。
- **SC-009**: 3難易度それぞれで100回以上の生成・探索開始を行っても、
  進行不能な開始状態または数字不整合が発生しない。
- **SC-010**: 初回利用を完了した端末で、通信不能時の起動、保存済み探索の再開、
  設定読込が全て成功する。

## Assumptions

- 既存の一人用ゲームと端末内保存を継続し、アカウント、オンライン同期、対人要素は対象外とする。
- 「探索中に得た素材の一部」は50%を端数切り上げで死亡地点へ移す。
- 憲章に従い、死亡時は装備中の道具、武器、防具も死亡地点へ移す。
- 死亡地点は複数保持でき、新規ゲームを確認付きで開始した場合だけ未回収分が消失する。
- チェックポイントの標準条件は到達であり、追加条件がある場合は探索開始前とHUDに表示する。
- チェックポイント確保対象は、入口または既存自陣から安全な開放マスで連結した範囲とする。
- 危険物除去後の数字は、現在有効な危険物数を表すよう更新する。
- スタミナの時間回復はアクティブな探索中だけ進み、メニュー表示中やアプリ非表示中は停止する。
- 「つづきから」は最新の正常な探索中断データを使い、破損時はバックアップを優先する。
- 画面レイアウトは刷新可能だが、必要情報、縦画面優先、操作領域、入力手段を失ってはならない。
